## 2. 计划依据与当前基线

本计划依据仓库中的《界面原型迭代计划》《界面原型迭代评估报告》《技术原型迭代计划》《技术原型迭代评估报告》、需求分析模型、技术原型 UML、软件架构文档、当前架构文档、接口契约、README 和课程提供的 `迭代计划.docx` 制订。

前两次迭代留下的经验将直接约束本次计划：

1. 先保证“可导入—可定位—可审阅—可保存—可展示”的闭环，不在最后阶段扩张到多模态、动态执行或完整 IDE 能力。
2. 接口契约和设计模型必须随实现同步更新，不能让前端、后端和文档描述互相漂移。
3. MinerU 和 Agent/LLM 是外部依赖，演示必须使用固定样例、明确状态和可解释失败方式；追溯无 Provider 时不得用静态关键词结果伪装 Agent 结果。
4. 每项“已完成”必须有代码、测试记录、截图/录屏或评审记录构成证据链。

截至 7 月 27 日，项目基线如下：

## 5. 设计、实现与评审要求

### 5.1 《设计模型》内容

最终《设计模型》在现有需求模型和技术原型 UML 上增量更新，不重复制造脱离源码的新模型，至少包含：

2. UC17“导出复现报告”的用例规约、基本流、空数据/生成失败等备选流。
3. 报告导出的 BCE 健壮性分析、设计类图或组件图、生成与下载时序图。
4. Project、PaperDocument、CodeRepository、TraceLink、AnalysisTask 与报告快照/文件之间的数据关系。
5. 当前 Web、Tauri、本地 FastAPI、SQLite、MinerU、LLM 和可选云端的部署边界。
6. 模型元素到 `frontend`、`backend`、`server` 和接口契约的映射，明确哪些是已实现、降级或规划项。

## 6. 测试计划与质量门禁

### 6.1 单元测试（xUnit）

- 使用 pytest（xUnit 风格）测试本地 FastAPI 后端核心子系统；新增 `pytest-cov` 生成语句覆盖率报告。
- 统计对象为 `backend/app`。允许排除数据库迁移版本、打包生成物和纯入口样板，但排除规则必须写入报告；API 路由、业务服务、领域模型和错误处理不得为了提高数字而排除。
- 覆盖项目管理、论文解析状态、仓库导入/文件访问、代码分析缓存、追溯生命周期、锚点恢复、Agent 会话/队列/流式事件/写确认、设置以及 UC17 报告导出。
- 门禁为：测试 100% 通过、语句覆盖率 **> 90%**、无随机失败；HTML 报告用于检查未覆盖行，XML 报告随提交材料归档。
- `server` 现有测试必须全部通过，但可选云同步不占用本次 90% 覆盖率统计口径；前端必须通过 `pnpm typecheck` 和 `pnpm build`。

建议验收命令如下，最终以仓库实际配置为准：

```powershell
Set-Location backend
uv run pytest --cov=app --cov-report=term-missing --cov-report=html --cov-report=xml --cov-fail-under=90
uv run ruff check app tests

Set-Location ..\server
uv run pytest -q
uv run ruff check tracelab_server tests

Set-Location ..\frontend
pnpm typecheck
pnpm build
```

## 11. 最终完成定义（Definition of Done）

构造迭代只有同时满足以下条件才可标记完成：

- 本计划 P0 范围全部实现，演示主路径在固定样例上连续通过；
- 《设计模型》与当前源码、数据库和 API 一致，并完成设计/代码评审；
- pytest 单元测试全部通过，`backend/app` 语句覆盖率超过 90%，报告可查；
- 功能、易用性、兼容性系统测试完成，P0/P1 缺陷均为 0；
- 前端类型检查和构建、后端与服务器 CI 检查通过；
- 最终版本按 README 可启动，安装包失败时存在经验证的 Web 备用运行方式；
- 答辩 PPT、演示脚本、备用证据、《构造迭代评估报告》和《项目总结报告》齐全；
- 所有裁剪项和已知限制被如实记录，界面、文档和答辩不把占位能力描述为已实现。
