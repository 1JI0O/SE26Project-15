# 俞冠廷任务派发：论文解析与导入

## 1. 任务目标

负责“论文进入 TraceLab 后形成可定位结构化内容”的完整后端能力。重点完成 MinerU 本地服务接入和统一论文 schema，使后续追溯模块不再依赖 `pypdf` 的粗粒度文本结果；同时完成 arXiv 固定样例导入演示。

本任务独立交付论文 API，不负责工作台 UI、代码仓库分析、LLM 追溯或 Agent。

## 2. 实施范围与优先级

### P0：必须完成

1. 将 `paper_parser.py` 改为解析器接口，至少提供 `MinerUParser` 和测试用 `StubParser`。
2. 通过 HTTP 调用本机 `mineru-api` 的异步任务接口，支持提交、轮询、超时、失败和结果读取。
3. 把 MinerU 原始结果转换为 TraceLab 统一结构：文档、页、章节、内容块、页码、块类型、文本和坐标锚点。
4. 原始 MinerU 输出与归一化结果分别保存；重复上传同一文件时允许复用解析缓存。
5. PDF 上传接口返回明确的 `queued/running/succeeded/failed` 状态，不在 HTTP 请求中无限等待模型。
6. 为 MinerU 不可用、解析超时、空 PDF、扫描 PDF 和异常输出增加测试。

### P1：本轮争取完成

1. 根据 arXiv 论文编号或 URL 下载 PDF，并复用同一解析链路。
2. 在 Apple Silicon 上验证 `hybrid` 后端；资源不足时可配置降级至 `pipeline`。
3. 提供固定论文的解析质量记录，至少检查标题层级、双栏阅读顺序、公式、表格和页码锚点。

### P2：时间允许再做

1. 解析进度事件或取消任务。
2. 对图片说明、跨页表格和参考文献建立更细的领域类型。

## 4. 接口契约

论文解析模块必须向追溯模块稳定提供以下最小数据：

```json
{
  "document_id": 1,
  "parser": "mineru",
  "parser_version": "recorded-at-runtime",
  "status": "succeeded",
  "pages": [
    {
      "page_number": 3,
      "blocks": [
        {
          "id": "p3-b12",
          "kind": "text",
          "text": "...",
          "bbox": [0.1, 0.2, 0.8, 0.3],
          "section_path": ["3 Method", "3.1 Residual Block"]
        }
      ]
    }
  ]
}
```

坐标统一归一化到 `0..1`，页码从 `1` 开始，块 ID 在一次解析结果内稳定。不得让调用方直接依赖 MinerU 的 `middle.json` 或特定后端字段。

## 5. 验收标准

- 本地 `mineru-api` 可被健康检查并完成一个固定论文解析。
- 关闭 MinerU 时接口返回可识别失败状态，不导致后端崩溃。
- 固定样例能在 UI 所需结构中显示章节、段落、页码和至少一种公式/表格锚点。
- 单元测试不要求下载模型或访问公网；真实 MinerU 测试使用显式 integration 标记。
- `ruff check backend/app backend/tests` 和论文模块测试通过。

## 6. 开发与合并约束

分支使用 `iter2-paper-mineru`。提交按“解析器接口、MinerU 适配、schema 转换、arXiv、测试”拆分，禁止把格式化整个仓库混入功能提交。只依赖已经冻结的论文契约；接口变更先写契约差异，再通知张朴更新前端。该分支在公共架构重构合入后再开始开发，合并顺序为论文模块第一批。
