# 秦浩翔任务派发：代码分析与张量流

## 1. 任务目标

负责“代码仓库进入 TraceLab 后形成可浏览、可编辑、可定位的静态模型”的完整后端能力，并由代码分析结果生成可交互张量流图。兼任本轮架构集成人，维护公共路由入口和最终 OpenAPI 合并。

本任务不实现论文解析、LLM 解释、Agent 对话或工作台视觉层。

## 2. 实施范围与优先级

### P0：必须完成

1. 保持 ZIP 导入闭环，统一 `.gitignore`、`.git/info/exclude`、`.DS_Store`、`._*`、`__MACOSX` 和常见构建目录过滤。
2. 将当前 `code_analyzer.py` 拆成仓库读取、忽略规则、Python AST 分析、文件编辑和图生成子模块，避免继续扩大单文件。
3. 输出完整过滤后文件树，以及类、函数、方法、导入、调用位置和源码行号。
4. 对 PyTorch `forward`、模块调用、张量运算、分支和残差合并生成节点/边；每个节点带 `source_path`、`line_start`、`line_end`。
5. 张量图布局与分析结果分离：后端输出语义图，布局服务输出坐标，前端不依赖硬编码占位节点。
6. 保证文件读取和保存只能访问已导入仓库中的允许路径，拒绝路径穿越和二进制文件。

### P1：本轮争取完成

1. 支持 GitHub 仓库 URL 的浅克隆或下载 ZIP，并复用同一过滤、分析链路。
2. 支持跨文件模块引用和常见 `nn.Sequential`、残差连接、拼接操作。
3. 为大型仓库生成摘要索引，文件树接口支持懒加载或分页所需元数据。

### P2：时间允许再做

1. 用运行时 shape propagation 验证部分静态张量形状。
2. 增加非 Python 文件的只读符号摘要。

## 4. 接口契约

代码分析必须提供稳定的符号和语义图结构：

```json
{
  "symbols": [
    {
      "id": "models/resnet.py::BasicBlock.forward",
      "kind": "method",
      "path": "models/resnet.py",
      "line_start": 24,
      "line_end": 31,
      "qualified_name": "BasicBlock.forward"
    }
  ],
  "tensor_graph": {
    "nodes": [{"id": "n1", "op": "conv2d", "symbol_id": "...", "shape": null}],
    "edges": [{"source": "n1", "target": "n2", "kind": "tensor"}]
  }
}
```

符号 ID 由规范化相对路径和限定名组成；源码位置均使用相对路径和 1 起始行号。无法确定 shape 时返回 `null` 和原因，禁止伪造确定值。

## 5. 验收标准

- 固定 PyTorch 仓库中被忽略文件不会出现在树、搜索或读取接口中。
- 至少生成一条包含分支与 merge 的张量流，并可从每个有效节点定位源码。
- 路径穿越、符号链接逃逸、二进制编辑和超大文件有明确拒绝结果。
- 代码仓库测试覆盖过滤、AST、读取、保存、图生成和异常输入。
- 全部后端测试和 `ruff check` 通过；OpenAPI 中无重复路径或 operation id。

## 6. 开发与合并约束

分支使用 `codex/iter2-code-flow`。先拆模块并保持行为，再增加图分析，避免在一个提交中混合重构和新算法。公共 `api/router.py` 只在各领域 router 已稳定后集中修改一次。该分支可与论文、追溯分支并行，合并顺序为论文模块之后、追溯模块之前。
