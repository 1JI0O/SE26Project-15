# 张朴任务派发：工作台与桌面客户端

## 1. 任务目标

负责所有用户可见交互和 Tauri 本地客户端壳，将论文、代码、张量流、追溯和 Agent 四类后端能力组合成稳定演示。当前 `ProjectWorkspaceView.vue` 约 2000 行，是最主要的前端冲突与性能风险，本任务先完成组件化，再接入新接口。

本任务不修改后端算法、数据库实体或服务实现。

## 2. 实施范围与优先级

### P0：必须完成

1. 将工作台拆成页面编排、论文阅读器、代码树/编辑器、张量流画布、追溯审阅和 Agent 面板；每个组件只接收 typed props/emits。
2. 将数据请求和页面状态抽到 `composables`/Pinia；避免文件切换时重复拉取整个工作台。
3. 文件树采用按需展开或虚拟化，缓存已读取文件；编辑器输入只更新当前 buffer，不触发整页计算。
4. 论文只读，支持按页/块定位；代码可编辑，保存前展示 dirty 状态，保存后刷新版本状态。
5. 张量流使用现有 SVG 或合适图形库渲染语义图，自动适应容器；点击节点跳转代码，禁止硬编码节点坐标作为业务数据。
6. 追溯关系显示来源、双侧证据、置信度和确认/驳回操作；Agent 写操作必须展示确认卡片。
7. 所有页面具备 loading、empty、error、degraded 状态。

### P1：本轮争取完成

1. 新建 `desktop/` Tauri 壳，复用同一 Vue 前端；实现用户授权的 PDF、ZIP 和代码目录选择。
2. Tauri 仅传递授权文件/目录，不向 Web 页面暴露任意文件系统能力。
3. 在 MinerU 或 LLM 不可用时，UI 展示降级原因并保持代码浏览可用。
4. 完成桌面与浏览器两种启动方式的演示脚本。

### P2：时间允许再做

1. 分栏尺寸持久化、快捷键、文件搜索和最近项目。
2. Agent 流式输出和图节点增量更新。

## 3. 代码所有权

可直接修改：

- `frontend/**`
- `desktop/**`（新建）
- `docs/contracts/frontend-mapping.md`（新建）
- `docs/demo/**`（新建）

正式运行前端仅为根目录 `frontend/`。`UIPrototype/frontend/` 是第一迭代原型归档，禁止继续开发或从中生成构建产物。

只读依赖，不直接修改：

- `backend/**`
- `database/**`
- `backend/app/api/router.py`
- `TechPrototype/技术原型迭代计划.md`

接口缺字段时，在对应后端成员的契约文档或 PR 中提出，不在前端使用临时字段名绕过。前端 API 已按 `paper-api.ts`、`repository-api.ts`、`trace-api.ts`、`workspace-api.ts` 分开；新增调用写入所属文件，不再扩大兼容入口 `api/projects.ts` 和 `types/api.ts`。

## 4. 组件边界

建议结构：

```text
frontend/src/features/
  papers/       PaperReader、页面/块定位、paper-api 映射
  repository/   RepositoryTree、CodeEditor、文件缓存
  tensor-flow/  TensorFlowCanvas、NodeInspector
  tracing/      TraceMatrix、EvidenceDrawer
  agent/        AgentPanel、ToolConfirmationCard
frontend/src/views/
  ProjectWorkspaceView.vue   仅负责布局和 feature 组合
```

后端 snake_case 只在 API 层转换一次，组件内部采用 camelCase。组件不得直接导入 `axios`，不得跨 feature 修改其他模块状态。

## 5. 验收标准

- `ProjectWorkspaceView.vue` 收敛为布局和编排页面，主要功能位于独立 feature 组件和 composable。
- 导入固定项目后可完成：查看论文、打开代码、保存编辑、查看追溯、点击图节点、确认/拒绝 Agent 工具。
- 1000 个文件节点的受控样例下，展开、切换和输入无明显长任务；无下半区空白或图表溢出。
- 桌面壳只能读取用户主动选择的文件/目录；浏览器模式仍可使用上传方式。
- `pnpm typecheck`、`pnpm build` 通过，并完成至少桌面 1440×900、浏览器 1366×768 两种尺寸检查。

## 6. 开发与合并约束

分支使用 `iter2-workbench-desktop`。第一批提交只做组件拆分且保持视觉行为，第二批接 API，第三批增加 Tauri，避免形成无法审查的大提交。该分支不与任何后端分支修改同一文件，可从已冻结的接口契约并行开发；最终在三个后端领域分支合入后进行一次联调提交。禁止提交 `node_modules`、`dist`、Tauri 编译产物或本地绝对路径配置。
