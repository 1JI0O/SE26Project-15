## 2. 迭代范围与验收边界

### 2.1 本迭代重点用例

1. **导入与解析项目**：通过 Web 上传或 Tauri 本地目录选择器导入论文 PDF 与代码仓库；系统按 `.gitignore`、`.DS_Store`、`__MACOSX` 等规则过滤无关文件，调用 MinerU 产出论文结构化内容，并解析代码文件树和 Python 基础符号。实现 GitHub 仓库 URL 与 arXiv 论文链接/编号的导入适配器，至少使用一个固定公开样例完成演示。
2. **论文—代码追溯浏览**：在左右分栏工作台中阅读只读论文、浏览完整代码树和可编辑代码文件。以代码静态特征、论文结构化片段和 LLM 证据解释共同生成候选追溯关系；用户可查看依据、置信度，并从论文片段或流程图节点定位到代码位置。
3. **代码编辑、分析与 Agent 协作**：在工作台编辑代码并保存；用户发起分析后获得可交互张量流图、追溯结果和冲突提示。Agent 可基于当前项目回答问题、提出修改建议，并仅在用户确认后通过受限工具执行保存、重新分析或更新流程图等操作。

### 2.2 不纳入本迭代验收的内容

- 高精度多模态图表/公式识别、跨语言静态分析和完整跨文件调用图；
- 训练过程动态追踪和全量张量验证；
- 多平台安装包发布、无人值守代码修改、生产级权限体系和 IDE 插件发布；
- 账号跨设备同步、多人协作、云端源文件托管和大规模 GitHub/arXiv 检索。

这些能力仅保留接口与架构扩展点；若核心闭环提前稳定，再作为加分探索项。

## 4. 技术方案设计

### 4.1 架构风格、技术选型与编程规范

采用**分层、前后端分离的本地优先架构**：Vue 3 + TypeScript + Vite 实现工作台，Tauri 提供受控本地目录选择，FastAPI + Python 承载业务 API 与分析编排，MinerU 提供论文结构化解析，SQLite 保存原型元数据，LLM API 仅为候选追溯补充证据解释和 Agent 对话能力。前端通过 OpenAPI 定义的 HTTP 接口访问后端，禁止直接读写数据库或任意本地路径。

前端遵循 TypeScript、Vue Composition API、ESLint/Prettier 既有配置；后端遵循 PEP 8、类型标注、Pydantic schema 与 pytest 测试约定。配置、密钥和本地路径不写入仓库，使用环境变量和示例配置文件管理。

### 4.2 架构视图、关键算法与评审

| 架构视图/设计项 | 本迭代产物 | 验收方式 | 负责人 |
|---|---|---|---|
| 逻辑视图 | 前端工作台、项目/工件 API、解析服务、追溯服务、数据存储的职责图；明确同步请求与后续异步任务的边界。 | 评审记录中确认职责不重叠，接口均可定位到所属模块。 | 秦浩翔、钱闵浩 |
| 开发视图 | `frontend`、`backend`、`docs`、`database`、测试目录的依赖关系；前端 API 层不得直接依赖数据库。 | 代码走查与目录说明。 | 张朴、钱闵浩 |
| 运行视图 | 本地开发时 Vite、Tauri、FastAPI、MinerU、LLM API、SQLite 与项目文件目录的运行关系；Tauri 仅向后端传递用户授权目录，解析/追溯任务通过统一任务接口返回状态。 | 按启动说明可运行；完成一次本地目录导入、MinerU 解析和 Agent 工具确认演示。 | 张朴 |

| 编程规范 | 前端遵循 TypeScript、Vue Composition API、ESLint/Prettier 既有配置；后端遵循 PEP 8、类型标注、Pydantic schema 与 pytest 测试约定。 | PR/提交前执行格式化、类型/测试检查；评审记录抽查。 | 全体成员 |

关键算法采用“**结构化解析—候选生成—证据解释—人工确认**”四步：MinerU 将 PDF 转为统一论文 schema；Python AST、文件路径和注释规则生成候选论文—代码关系；LLM 仅基于候选上下文输出依据与置信度；用户确认后才将关系写入追溯记录。张量流图以节点、边和代码定位信息组成的图数据返回前端，节点点击跳转到对应代码位置。

架构文档在 7 月 16 日立会上评审，评审关注职责边界、数据模型、接口契约、可降级行为与安全边界；问题记录进入缺陷清单并在后续工作包中闭环。

## 5. 技术原型实现与预期成果

1. 《技术原型架构说明》：至少包含逻辑、开发、运行、数据四个视图，以及关键扩展点说明。
2. 《API 与样例数据说明》：覆盖项目创建、论文/代码上传、工作台读取、代码保存、追溯矩阵和分析触发接口。
3. 可运行的技术原型：实现并演示本计划定义的 3 个典型用例；前端与后端通过统一接口联调。
4. 解析与追溯样例：固定论文和 Python/PyTorch 代码仓库的输入、MinerU 结构化输出、统一 schema、静态分析与 LLM 结合的候选追溯结果、证据解释与已知限制。
5. 测试与评审材料：单元/接口/端到端测试记录、架构与接口评审记录、缺陷清单和修复记录。
